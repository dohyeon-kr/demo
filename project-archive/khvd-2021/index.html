필요한 시스템을 만든다

기획과 디자인을 제외한 구현과 운영 전반을 책임했고, 이 프로젝트를 계기로 AWS 사용법을 익혀 서버 인스턴스까지 직접 관리하기 시작했습니다. 웹·API·Script·Excel을 직군별 산출물로 나누기보다 실제 문제를 해결하는 수단으로 보게 된 경험입니다.

결과물의 형태보다 실제로 쓰이고 운영을 개선하는지가 중요하다는 관점이 이때부터 분명해졌습니다.

굿즈 판매 장부

판매 기록, 재고, 정산 정보를 따로 적으면서 같은 사실을 여러 번 입력하고 있었습니다. 바쁜 전시 현장에서 누락 가능성이 커 보였고, 별도 요청을 받기 전에 먼저 Excel 장부를 만들어 제안했습니다.

Single input

판매 입력을 하나의 주 입력원으로 삼고 재고·전체 매출·판매 주체별 정산·마감 결과를 다른 Sheet에서 파생했습니다.

Function-only

VBA나 매크로 없이 Excel 함수로 자동 계산해 현장 PC에서 바로 사용할 수 있게 했습니다.

Single writer

캐셔 PC 한 대에서 기록 담당자가 순서대로 입력하는 실제 운영 방식에 맞춰 불필요한 동시성 복잡도를 만들지 않았습니다.

Operational use

전시 종료까지 계속 사용되며 마감 정산, 재고 파악, 추가 반입 판단과 여러 판매 주체의 정산금 분배를 지원했습니다.

이어진 방식

한 번의 입력에서 여러 결과를 파생시키고 사람이 기억하거나 중복 입력해야 하는 지점을 줄이는 방식은 이후 운영 자동화와 내부 도구에서도 반복되는 문제 해결 패턴이 됐습니다.
