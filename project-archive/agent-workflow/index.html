위임할수록 경계를 더 명확하게

구현, 리뷰, 테스트, lint, 탐색, GitHub, Jira 등 역할별 서브에이전트를 정의하고 어떤 상황에서 누구에게 위임할지 기준을 둡니다. 푸시 직전에는 diff 리뷰 결과가 approve일 때만 통과하는 게이트를 두고 판정과 토큰 사용량을 감사 로그로 남깁니다.

AX의 목표를 AI 사용량 증가가 아니라 실행 비용과 피드백 비용을 줄이면서 품질을 유지하는 것으로 정의했습니다.

작업 단위를 바꾸는 구조

Parallel worktrees

Conductor와 Git worktree를 사용해 작업별 실행 공간을 분리하고 여러 Agent 작업을 병렬화합니다.

Figma as context

공식 Figma MCP와 별도 Comment MCP로 디자인 링크·Revision·Comment를 Agent의 직접 입력으로 사용합니다.

TDD as boundary

테스트를 구현 이후 검증이 아니라 Agent가 건드릴 수 있는 작업 경계와 완료 조건으로 적극 활용합니다.

Result-centric review

모든 코드 diff를 기본 단위로 읽기보다 Storybook, 실행 화면, 프로토타입 등 실제 결과의 정합성을 우선 확인합니다.

Tool interface

ChatGPT를 GitHub·Notion·Figma·SigNoz의 맥락을 탐색·비교·기록하는 인터페이스로 사용합니다.

Measure forward

tokens/task, lead time/task, human intervention, CI 실패와 hotfix를 함께 보며 자동화 효과를 이후 데이터로 검증합니다.

자동화가 판단을 숨기지 않게

규칙을 문서로만 두지 않고 Hook으로 강제하며, 자동화가 스스로 판정 흔적을 지우지 않도록 감사 로그를 남깁니다. 비용이 줄어도 사람이 다시 수행해야 할 시간이 늘거나 품질이 나빠지면 개선으로 보지 않는다는 평가 원칙을 둡니다.
