포팅보다 더 큰 문제

홈·포인트·퀘스트·출석체크·장소미션·응모·마이페이지와 기존 적립 기능을 네이티브 환경으로 이관하고, 카카오 로그인·소셜 회원가입·계정 연동·알림까지 연결했습니다. 출시 이후에는 화면 수정, 스토어와 OTA 운영, 사용자 오류 추적, 디자인·백엔드 변경 검증이 더 중요한 문제로 바뀌었습니다.

웹을 앱으로 복제하는 것이 아니라, 앱을 계속 바꿀 수 있는 개발·리뷰·배포·관측의 루프를 함께 만든다.

확장한 범위

Product UI Architecture

디자인 토큰, 공용 버튼, 서브헤더, 바텀시트, 모달 호스트를 화면에서 분리하고 Figma 개정본 기준으로 화면군을 재구현했습니다.

Release & OTA

EAS development·preview·production 티어, runtimeVersion baseline, 핫픽스 백머지, prerelease SDK gate와 서버 지시 업데이트 경로를 구성했습니다.

Observability

SigNoz 에러 리포팅과 traceparent 전파를 연결해 사용자 오류에서 API 응답과 Backend trace까지 추적할 수 있게 했습니다.

Review Surface

Storybook을 화면 단위 User Flow QA 카탈로그로 재구성하고 UI Picker, MSW, Figma Frame Link를 붙여 피드백 단위를 실물 중심으로 바꿨습니다.

AI-native workflow

Figma 링크를 Agent의 구현 Context entry point로 쓰고, Comment MCP로 수정 요청의 위치 맥락을 보완했습니다. AI가 구현하는 비중이 커질수록 TDD를 작업 경계와 완료 조건으로 활용하고, 코드 diff만 보는 대신 Storybook·실행 앱의 실제 결과를 중심으로 리뷰했습니다.
