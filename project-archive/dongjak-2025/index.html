방문쿠폰

동작구 상권 활성화 사업에서 시민·상점·운영자를 연결해 쿠폰 발급, 현장결제, 사용 확인과 월별 정산까지 처리한 시스템입니다. 4인 개발팀의 개발 리드로 전체 데이터 흐름과 핵심 상태 모델을 설계했습니다.

전년도 실패를 설계 입력으로

2024 시스템에서는 마일리지 차감, 쿠폰 생성, 예산 차감이 분리된 쓰기로 실행됐고 동시 요청과 취소·복원 흐름에 정합성 위험이 있었습니다. 2025에서는 이를 팀원의 문제로만 보지 않고 리드의 설계·리뷰·테스트 가드레일 부족까지 포함해 회고했습니다.

시스템 초안을 먼저 작성하고 데이터 흐름, 프론트 화면, 쿠폰·결제·정산의 상태 모델을 선행 설계한 뒤 팀 구현을 이끌었습니다.

핵심 설계

Concurrency & Transaction

NestJS CLS와 Prisma 트랜잭션 컨텍스트를 연결하고 쿠폰 발급·사용과 결제 주문에 Serializable 격리를 적용했습니다.

Payment Consistency

PG 서버 알림을 실제 상태 확정 기준으로 삼고 PENDING 주문만 처리해 중복 콜백을 막았습니다. 내부 처리 실패 시 PG 취소 보상 흐름을 두었습니다.

Identity & Access

PASS 본인인증 결과를 서버에서 재검증하고 상점 사업주 로그인과 정산 동의에 연결했습니다. 상점별 데이터 접근은 RBAC와 서버 Guard로 제한했습니다.

Operations

월별 상점 정산, 서명·증빙 제출, 예산·회차·한도 변경, 추첨·문자 발송·Excel 리포트를 운영 도구와 스크립트로 지원했습니다.

운영에서 배운 것

외부 메시징 API 테스트 스펙 오해로 실제 사용자에게 테스트 문자가 발송된 사고를 겪었습니다. 정정 문자와 공지 UI로 대응한 뒤, 외부 API 스펙을 타입화하고 비운영 발송을 내부 채널로 우회했으며 실제 발송 테스트를 별도 명령으로 격리했습니다. 개발 완료 조건을 코드뿐 아니라 운영 경계와 사고 전파까지 포함해 보게 된 사례입니다.
