매장 키오스크

여러 매장에 배포되는 키오스크 애플리케이션의 개발 전반을 맡았습니다. PHP·jQuery 기반 UI와 매장별 데이터 가공을 구현했고, 초기 배포 구조 때문에 실제로 발생한 매장별 패치 누락을 동기화 자동화로 해결했습니다.

프로젝트 아카이브로 돌아가기
Period2020.04 — 08
RoleApplication Development
StackPHP · jQuery · SCSS
DataPython
Context

같은 제품을 여러 매장에 다르게 배포하기

키오스크의 메인 화면은 매장 정보, 카탈로그와 이벤트 콘텐츠로 들어가는 허브였습니다. 외부에서 제공받은 3D 매장 둘러보기 Viewer를 키오스크 UI에 넣고, 외부 링크 중에서도 하단 Navigation을 계속 유지해야 하는 콘텐츠는 iframe으로 연결했습니다.

제품 자체는 하나였지만 매장마다 보여줘야 하는 정보와 데이터가 달랐습니다. 제공받은 매장 정보와 카탈로그를 Python으로 전처리·정렬하고, 매장별 설정값을 기준으로 공통 코드가 다른 데이터와 동작을 사용하게 구성했습니다.

01 · HUB

매장 콘텐츠 진입점

매장 소개, 카탈로그, 이벤트와 3D Viewer를 한 키오스크 경험 안에서 연결했습니다.

02 · CONFIG

매장별 설정

공통 애플리케이션이 매장별 PHP 설정값에 따라 데이터와 동작을 달리하도록 구성했습니다.

03 · DATA

배포 전 데이터 가공

매장별 원본 데이터를 Python으로 정리해 키오스크가 바로 소비할 수 있는 배포 형태로 만들었습니다.

04 · EMBED

기존 콘텐츠 재사용

새로 만들 필요가 없는 외부 Viewer와 콘텐츠는 iframe 등으로 통합해 구현 범위를 조절했습니다.

Initial Architecture

모르는 구조를 폴더 복제로 우회했다

매장별 subdomain이 필요했지만 당시에는 reverse proxy routing이나 PHP에서 host를 읽어 같은 애플리케이션을 분기하는 구조를 충분히 알지 못했습니다. 그래서 각 subdomain에 대응하는 별도 폴더를 만들고 공통 코드를 복제했습니다.

개발 자체는 가능했지만 운영 단계에서 문제가 드러났습니다. 동일한 코드가 여러 폴더에 존재하므로 한 매장의 공통 패치를 수정하고 다른 매장 폴더에는 반영하지 않는 일이 실제로 생겼습니다. 구조적 중복이 단순한 코드 미관 문제가 아니라 매장마다 서로 다른 버전이 배포될 수 있는 운영 리스크가 된 것입니다.

Failure mode

코드 중복의 비용은 “같은 코드가 많다”가 아니라, 같은 변경이 모든 운영 인스턴스에 동일하게 도달한다는 보장을 잃는 것이었다.

Automation

전면 재설계보다 위험을 먼저 닫기

가장 이상적인 해결은 매장 폴더 복제 자체를 없애고 하나의 코드베이스가 host나 설정으로 분기되게 다시 만드는 것이었을 수 있습니다. 하지만 이미 여러 매장이 운영되는 상황에서 전체 구조를 바꾸는 것은 비용과 리스크가 컸습니다.

대신 공통 파일을 기준 폴더에서 각 매장 폴더로 복사하는 synchronization script를 만들었습니다. 이후 공통 패치 누락은 거의 사라졌고, 당장의 운영 리스크가 크게 줄었습니다.

SCSS compile 과정도 script로 단순화해 필요한 output이 없으면 생성되도록 처리했습니다. 지금처럼 성숙한 build tooling을 사용하는 프로젝트는 아니었지만, 반복되는 수작업이 실제 오류로 이어지는 지점을 하나씩 자동화했습니다.

Problem매장별 복제 폴더 때문에 공통 패치 반영이 누락될 수 있음
Constraint운영 중인 구조 전체를 갈아엎는 비용이 문제 규모보다 큼
Control공통 파일 동기화 script로 모든 매장 폴더에 같은 변경을 전파
Decision운영 문제가 닫힌 뒤에는 구조적 완벽함을 위해 추가 리팩터링하지 않음
Tradeoff

구조의 아름다움보다 실제 장애를 만드는 위험을 먼저 제거하고, 해결 뒤의 추가 리팩터링은 비용 대비 효과로 판단한다.

What this project shows

좋지 않은 초기 구조에서도 운영 리스크를 찾아 현실적인 통제로 바꾼다.

현재라면 다른 구조를 선택하겠지만, 당시에는 실제 패치 누락이라는 문제를 발견한 뒤 재설계보다 빠른 동기화 자동화로 위험을 닫았습니다. 완벽한 설계보다 문제의 비용에 맞는 해결을 선택한 초기 사례입니다.
