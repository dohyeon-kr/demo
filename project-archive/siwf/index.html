사용자 화면과 운영 화면을 함께

WordPress를 데이터 원천과 REST API 계층으로 사용하고, 같은 Next.js 애플리케이션 안에 사용자 화면과 별도 admin route를 구성했습니다. WordPress 기본 관리자 UI를 깊게 커스터마이징하는 대신 실제 사용자 화면의 맥락을 유지한 전용 관리자 화면을 만들었습니다.

Custom Admin UX

배너 순서 DnD, 메뉴 추가·삭제·순서·링크·노출 설정을 사용자 화면과 유사한 맥락에서 편집하도록 구성했습니다.

Small Content Language

metadata 필드에서도 bold·italic·줄바꿈을 표현할 수 있도록 작은 토큰 문법을 두고 프론트에서 파싱했습니다.

API Abstraction

WordPress Custom REST API의 반복 요청·응답 처리와 생성 인자를 class로 모듈화해 다른 프로젝트에도 재사용했습니다.

External Game

외부 게임 개발자와 필요한 데이터 형식을 맞추고 Custom REST API로 제공하며 번들 통합을 담당했습니다.

네트워크 위치까지 포함한 SSR 이해

클라우드 전환 후 Next.js SSR이 외부망의 WordPress API를 호출하도록 되어 있었지만, 이전된 서버가 사설망에 있고 outbound가 막혀 서버 측 요청이 실패했습니다. 당시에는 내부 통신 경로를 별도로 설계할 개념이 부족해 사용자 브라우저에서 접근 가능한 API 호출은 CSR로 전환해 정상화했습니다.

이 경험 이후 SSR/CSR을 렌더링 방식만이 아니라 “요청이 어느 네트워크 위치에서 출발하는가”까지 포함해 이해하게 됐습니다.

첫 명시적 검증 기준

클라우드 전환 대행사가 반복적으로 테스트 기준을 요구하면서 사용자 기능별 정상 동작을 확인하는 수동 E2E 문서를 처음 직접 정의했습니다. 애플리케이션의 정상 상태를 개발자의 머릿속이 아니라 외부 업체와 공유 가능한 기준으로 문서화한 첫 경험이었습니다.
