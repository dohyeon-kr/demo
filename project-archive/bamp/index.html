BAMP

광고기획 동아리에서 부회장으로 활동하며 출석·점수 운영, 브랜드 가이드, 3D 캐릭터, 모집 홍보, 행사 프로그램, 웹사이트와 실물 제품 프로토타입까지 만들었습니다. 공식 직책보다 실제 역할은 새로운 아이디어를 먼저 형태로 만들어 보여주고 조직이 써볼 수 있게 하는 전략기획·프로토타이핑에 가까웠습니다.

Working Style

말로 설득하기보다 먼저 보여주기

새로운 프로그램이나 도구 아이디어가 생기면 문서로 길게 설명하기보다 먼저 시안이나 동작하는 프로토타입을 만들었습니다. 운영진은 완성될 결과를 직접 보고 판단할 수 있었고, 긍정적이면 실제 운영에 적용했습니다.

문제를 고치는 일만 가치 있다고 생각하지도 않았습니다. 송년회에서 랜덤 당첨자를 TV 화면에 보여주는 Flash 프로그램처럼 운영 효율과 직접 관련이 없어도 구성원 경험을 더 재미있게 만드는 일이라면 만들 가치가 있다고 봤습니다.

Early pattern

추상적인 아이디어를 논쟁하는 시간을 줄이고, 작게라도 실체를 만들어 사람의 반응을 기준으로 다음 판단을 한다.

이 방식은 이후 제품 개발에서도 반복됩니다. 기획 단계에서 완벽한 합의를 오래 만드는 것보다 prototype, Storybook, 실제 화면처럼 이해관계자가 직접 판단할 수 있는 Surface를 먼저 만드는 성향의 초기 형태였습니다.

Brand System

로고를 넘어 반복해서 쓸 수 있는 언어 만들기

기존 로고는 있었지만 어떤 색과 폰트로, 어떤 방식으로 사용해야 하는지 명시적인 기준이 없었습니다. 로고 사용법·색상·폰트 가이드를 정리하고 카페·블로그·SNS를 각 채널 특성에 맞게 디자인하면서 제가 제작하는 범위 안에서는 시각적 일관성을 유지했습니다.

밤디 — 로고를 캐릭터로 확장

기존 박스형 로고의 흰 윗부분을 “아이디어가 들어 있는 상자의 투명한 윗면이 빛나는 모습”으로 해석했고, 그 형태를 얼굴로 확장해 `밤프 + buddy`라는 이름의 캐릭터 ‘밤디’를 만들었습니다. 대학생 페르소나에 맞춰 나그랑 티셔츠, 슬랙스와 가방을 입혔습니다.

3ds Max에서 리깅된 원본을 만들고, 필요할 때마다 포즈와 Scene을 바꿔 렌더링해 공지와 홍보물에 반복 사용했습니다. 이후 기수에서는 제가 만든 3D 파일을 그대로 쓰기보다 새 그림체로 다시 그렸지만 얼굴과 의상 같은 특징이 남아 다양한 배리에이션으로 이어졌습니다.

Why it matters

브랜드를 한 번 쓰는 그래픽이 아니라 조직 구성원이 변형하고 재사용할 수 있는 문화 자산으로 만든 초기 경험.

Organization Systems

운영에서 반복되는 일을 작은 도구로

출석과 추후 혜택에 연결되는 점수 계산은 Excel에서 자동으로 동기화되도록 정리했고, 기존에 없던 활동 수료증안을 제작했습니다. 운영진 사진 공개를 부담스러워하는 구성원을 위해 실제 얼굴 사진 대신 직접 그린 일러스트로 운영진을 소개하는 형식도 제안했습니다.

01 · OPERATION

출석·점수 계산

수작업 계산을 줄이기 위해 입력과 점수 결과가 Excel에서 자동으로 연결되게 정리했습니다.

02 · PROOF

활동 수료증

동아리 활동을 외부에서도 증명 가능한 형태로 남기기 위해 최초 수료증 시안을 만들었습니다.

03 · PRIVACY

운영진 일러스트

얼굴 사진 공개 부담이라는 현실 제약을 사진 대신 그림이라는 새로운 모집 표현 방식으로 바꿨습니다.

04 · EVENT

행사 프로그램

영상 편집과 Flash 추첨 프로그램처럼 행사 경험을 강화하는 작은 도구를 직접 제작했습니다.

24기 모집 — 아이디어의 비주얼 연출

다음 기수 운영진이 제안한 뽑기 기계 콘셉트를 제가 아이디어를 낸 것으로 포장하지 않습니다. 제 역할은 그 기획을 3D 오브젝트, 화면 구성, 타이포그래피, 색상과 전체 분위기로 옮겨 실제 모집 포스터로 연출하는 것이었습니다. 전 기수 인터뷰 영상은 편집을 맡았고 운영진 소개용 일러스트도 직접 제작했습니다.

Experiments

잘 만든 것과 실제로 쓰이는 것 사이

BAMP 웹사이트

기존 카페에서 기획서 파일 용량 문제가 있었고, 광고·마케팅 동아리인 만큼 직접 웹사이트를 만드는 것 자체도 재미있는 역량 표현이라고 생각했습니다. 실제 사용 가치를 고민하면서 여러 곳에 흩어진 수상작을 한 인터페이스에서 찾는 아카이브와 선배들의 공모전 노하우 콘텐츠를 추가했습니다.

사이트는 공개됐지만 오래 운영되지 않았습니다. 기존 카페와 블로그를 없애지 않은 상태에서 채널 하나가 더 생겼고, 새 사이트를 계속 운영할 주체와 강한 사용자 니즈가 없었습니다. 당시에는 “잘 만들었는데 홍보가 부족했다”고 생각했지만, 지금은 채널 추가 자체가 운영 비용이며 사용 이유와 소유자가 없는 제품은 기능 완성도와 무관하게 사라진다고 봅니다.

내일일기

핵심 아이디어는 다른 팀원이 제안한 자기선언형 미래일기장이었습니다. 프로젝트 참여자를 먼저 모으고 약 15명 규모의 팀을 구성했으며, 저는 브랜드 표현과 표지·간지·내지, 페이지 기획을 실제 편집디자인으로 옮겼습니다. 인쇄된 실물 프로토타입까지 만들었지만 크라우드펀딩을 열기 전에 중단했습니다.

지금 돌아보면 약 15명을 움직일 만큼 목표와 역할이 선명하지 않았고, 실제 핵심 실행 인력은 약 5명이었습니다. 현재라면 작은 핵심팀을 먼저 두고 나머지 참여자는 테스터나 후원자로 설계했을 것입니다.

Retrospective

무언가를 만들 수 있다는 것과, 사람들이 계속 사용할 이유·운영 주체·적절한 팀 구조를 만드는 것은 전혀 다른 능력이다.

Connection

개발 이전에도 같은 방식으로 일했다

당시에는 개발자가 아니었지만 지금의 작업 방식과 연결되는 부분이 많습니다. 조직의 마찰을 발견하고, 필요한 도구의 형태를 고정하지 않고, 먼저 프로토타입을 만들어 보여주고, 실제 사용 반응을 보며 다음 판단을 했습니다.

차이가 있다면 지금은 여기에 운영 비용, 권한, 데이터, 테스트와 리스크라는 엔지니어링 언어가 더해졌다는 점입니다. 디자이너에서 개발자로 완전히 다른 사람이 된 것이 아니라, 원래 하던 문제 해결 방식에 소프트웨어라는 더 강한 도구가 붙었다는 커리어 서사를 보여주는 프로젝트입니다.
